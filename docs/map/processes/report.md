# report

Turning a session's verified samples into a number a lab can act on, and a file it can hand
over.

**Input** — a session id and a signed-in medtech.
**Output** — a persisted [`Report`](../objects/Report.md) row and a CSV file in Downloads.

**consumes** [`Session`](../objects/Session.md), [`Sample`](../objects/Sample.md),
[`Detection`](../objects/Detection.md)
**produces** [`Report`](../objects/Report.md)

## Movement

1. **Require auth and ownership.** `GenerateSessionReportUseCase` fails if there is no live
   Supabase user, if the session is missing, or if the session is not owned by the current user
   (`domain/usecase/records/GenerateSessionReportUseCase.kt:38-46`). **This is the one flow
   that does not work offline** — capture, verification, and manual capture all do.
2. **Gather.** Fetch the session's non-flagged samples and each one's detections
   (`domain/usecase/records/GenerateSessionReportUseCase.kt:48-51`).
3. **Count.** `getConfirmedEggCountsForSession` groups by `COALESCE(expert_class, class_label)`,
   joins to samples, and excludes flagged samples, repeat samples, and false positives
   (`data/local/dao/DetectionDao.kt:33-52`). Read that WHERE clause before changing anything
   about counting — see the caveat in [`validate`](validate.md).
4. **Normalise species** to canonical names, falling back to the raw label when unrecognised
   (`domain/usecase/records/GenerateSessionReportUseCase.kt:54-56`, `:99-102`).
5. **Compute EPG** per species: `count × 24`, the hardcoded Kato-Katz multiplier
   (`core/util/EpgCalculator.kt:12-17`,
   `domain/usecase/records/GenerateSessionReportUseCase.kt:57`). The citation for that constant
   is still an open TODO in the source (`core/util/EpgCalculator.kt:6`), and replacing it with a
   DOH-validated lookup table is Phase 2.
6. **Derive the summary.** Positive species are those with EPG > 0, sorted;
   `total_samples` counts non-repeat samples
   (`domain/usecase/records/GenerateSessionReportUseCase.kt:58-60`).
7. **Build the CSV** — a comment-prefixed header block (report id, session id and label,
   timestamps, device id, generated by, totals, positive species, per-species EPG) then one row
   per detection, or one row for a sample with no detections
   (`domain/usecase/records/ReportCsvBuilder.kt:14-34`, `:36-60`).
8. **Write the file** to the device Downloads directory as
   `agarthavision-session-{sessionId}-{reportId}.csv`, with fallbacks to app-external and
   internal storage (`data/repository/DownloadsReportFileStore.kt:17-28`).
9. **Insert the row** with `supabase_status = pending`, then push it —
   row only, no file upload (`domain/usecase/records/GenerateSessionReportUseCase.kt:81-95`,
   `data/supabase/SyncReportUseCase.kt:25-35`).

Sharing is a separate user action: `FileProvider` plus an `ACTION_SEND` intent from Session
Detail (`ui/records/SessionDetailScreen.kt:355-357`).

## Live EPG, without a report

`SessionEggCountUseCase` runs the same aggregate and the same multiplier without writing
anything (`domain/usecase/reports/SessionEggCountUseCase.kt:19-29`). It is what Session Detail
displays before anyone generates a report. It returns empty when signed out
(`domain/usecase/reports/SessionEggCountUseCase.kt:20`).

## Hits

- **The multiplier.** `EpgCalculator.MULTIPLIER` is one constant read by both the live readout
  and the persisted report. Changing it changes every future number and none of the stored
  ones — reports are snapshots and are never recomputed.
- **The counting rule.** Any change to the WHERE clause in
  `data/local/dao/DetectionDao.kt:33-52` silently changes EPG everywhere.
- **The CSV column set**, which is a downstream consumer contract even though nothing in this
  repo parses it.
- Report generation is idempotent in the sense that it always creates a *new* row; it never
  updates an existing one.

## Does not hit

- **Existing reports or their files.** Regenerating writes a new row and a new file under a new
  report id. Old CSVs stay on disk under their old names, and stale files are never cleaned up.
- **Storage.** The CSV never reaches Supabase — only the row does. `csv_file_path` is a
  device-local path that no other client can resolve.
- **Sample or detection state.** Reporting is read-only over both. Generating a report does not
  mark anything as reported.
- **The `administrative` report type.** Named in a migration comment, rejected by the CHECK
  (`supabase/migrations/0008_reports.sql:9`, `:17`). Cross-session reporting is Phase 2.
